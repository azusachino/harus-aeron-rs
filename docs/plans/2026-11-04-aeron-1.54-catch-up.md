# Catch up to Aeron 1.54.0

## Outcome and scope

Drafted 2026-11-04. Move the reproducible upstream reference from the current `release/1.50.x` snapshot to the exact Aeron `1.54.0` release, then close compatibility gaps in the implemented Rust driver/client and managed Archive boundaries. Reconcile newer functionality and cluster changes explicitly without claiming full upstream parity.

[Tracking issue #44](https://github.com/azusachino/harus-aeron-rs/issues/44) owns live status. This document owns the source analysis, dependency order, acceptance criteria, and verification design. This is a plan, not an upstream-pin change or authorization to release/deploy. Existing issue [#23](https://github.com/azusachino/harus-aeron-rs/issues/23) still owns release acceptance; this plan does not silently rewrite its 1.50.x contract.

and verifies Java CnC/IPC/UDP smoke plus a 1,000-message soak. That advances the S0
reference slice; the inventory and deeper runtime work below remain tracked in
issue #44. The repository's `deploy/interop/INTEROP_STATUS.md` records the actual
source/JDK evidence.

## What changed and how it maps to Rust

| Change family | Upstream evidence | Rust observation and disposition |
| --- | --- | --- |
| Later 1.50.x backports | 1.50.5 spy-array race; 1.50.6 transport cleanup, batching, and send/receive-path changes; 1.50.7 C declaration fix | The March snapshot cannot be assumed to contain September fixes. Compare applicable spy/lifecycle behavior; C declaration/build fixes do not transfer mechanically to Rust. |
| Persistent subscriptions, 1.51 | New Archive-client feature, plus later replay/image recovery fixes | A new client orchestration boundary, not a new field in the Archive control XML. Plan separately from restoring existing Archive connection compatibility. |
| Resolver and native-resource lifecycle, 1.51–1.52 | NameResolverAgent split; async executor becomes NativeResourceAgent; log-buffer create/free leaves conductor in dedicated modes | Rust has resolver primitives and synchronous conductor/log-factory code. Audit real resolver wiring and conductor stalls; define a bounded scheduling design before adding a new agent. |
| Archive schema, 1.53 | Compare [old XML](https://github.com/aeron-io/aeron/blob/8e0cdb2f92800a047c0066028444b790a80fe593/aeron-archive/src/main/resources/archive/aeron-archive-codecs.xml) with [target XML](https://github.com/aeron-io/aeron/blob/454da1e4e6c7edf3dd6d34878512d3243384992a/aeron-archive/src/main/resources/archive/aeron-archive-codecs.xml) | Exact diff: version 13 becomes 14 and `ConnectRequest` template 2 is removed. Other message definitions are unchanged. Rust still encodes/dispatches template 2; template 58 `AuthConnectRequest` is the required modern entry point. Avoid rewriting unaffected codecs. |
| Protocol-version fields | Target [AeronArchive.Configuration](https://github.com/aeron-io/aeron/blob/454da1e4e6c7edf3dd6d34878512d3243384992a/aeron-archive/src/main/java/io/aeron/archive/client/AeronArchive.java) and [CnC descriptor](https://github.com/aeron-io/aeron/blob/454da1e4e6c7edf3dd6d34878512d3243384992a/aeron-client/src/main/java/io/aeron/CncFileDescriptor.java) | Archive runtime control protocol remains 1.12.0, matching Rust. CnC remains 0.2.0, matching 512. XML schema semanticVersion is 5.2 at both references; it is a separate field. Do not bump unrelated versions to the Aeron release number. |
| Archive request ownership, 1.53 | Only accept requests/close from the image that established the control session | `ArchiveService::poll_control_requests` drops the callback header and queues only bytes; its session map associates IDs with response publications. Preserve source-image identity and enforce it before mutations/deduplication. This is a source-level gap, not a fresh exploit reproduction. |
| Truncation while replaying, 1.52 | Stop concurrent replays before deleting recording segments | Rust `ArchiveService` explicitly returns “cannot truncate recording with active replay.” Change only the affected recording's replay lifecycle; test persisted results and other recordings. |
| Archive error/lifecycle fixes, 1.52–1.54 | Empty-replay rejection, max recording admission, abort on non-recoverable control errors, timeout cleanup, catalog sync | Audit actual managed-service behavior. Rust catalog serialization already calls `sync_all`; Java interruption-specific tests do not establish a missing Rust fsync. |
| Counter lookups, 1.54 | [RecordingPos](https://github.com/aeron-io/aeron/blob/454da1e4e6c7edf3dd6d34878512d3243384992a/aeron-archive/src/main/java/io/aeron/archive/status/RecordingPos.java) requires archiveId in signatures and documents NULL_VALUE as legacy wildcard | Rust already takes archive_id and supports the wildcard. Verify matching semantics and multi-Archive isolation; do not remove valid wildcard behavior simply because overloads were removed. |
| Packet validation, 1.53 | Validate all frames in a packet; target flyweights add validation contracts | Rust checks the first header/version and several frame lengths, then processes bundled data incrementally. Audit the entire receive/conductor path for malformed later frames and side effects before rejection. Include SETUP, SM, NAK, RTTM, heartbeat, padding, and alignment rules. |
| SM bounds, 1.51 and later correction | [SendChannelEndpoint](https://github.com/aeron-io/aeron/blob/454da1e4e6c7edf3dd6d34878512d3243384992a/aeron-driver/src/main/java/io/aeron/driver/media/SendChannelEndpoint.java) validates frames and publication-relative bounds; target allows half a term behind and 1.5 terms ahead | Rust `NetworkPublication::poll_control` matches session/stream and forwards SMs to flow control without a visible sender-relative range gate. Check earlier endpoint validation before fixing; test latest bounds rather than the superseded symmetric rule. |
| Live receiver/MDC/untethered fixes, 1.53–1.54 | Min flow control must retain live receivers, MDC removes the right inactive destination, untethered LINGER must not block DRAINING | Rust has these strategy/lifecycle surfaces with bounded integration coverage. Add separate real driver scenarios; do not interpret the fix as proof the same bug exists here. |
| MPSC ordering, 1.54 | [PR #2156](https://github.com/aeron-io/aeron/pull/2156) fences a negative claim marker before payload so unblock scanning cannot mistake payload for a record on ARM64 | Rust's implementation reserves tail and publishes positive length after payload; the shown write path has no matching negative-marker/unblock protocol. Prove its own reservation/reuse/progress invariants with Loom before deciding whether an algorithm change is needed. A copied fence alone would not port upstream's protocol. |
| Controlled API and poll rotation, 1.53 | controlledPeek/position setters removed; round-robin wrap duplication fixed | controlled_poll remains valid. Rust already advances its image start index modulo image count. Verify fairness and controlled abort/commit behavior; no blanket API removal or assumed rotation bug. |
| Timestamping and new configuration | Every packed frame receives timestamp writes; 1.54 adds UDP traffic class, affinity validation, and renamed C options | Rust parses timestamp offsets but has explicit runtime limits. Distinguish parse-only support, configuration gaps, and platform-specific affinity APIs. Avoid implying support from successful URI parsing. |
| Cluster recovery and service lifecycle | VersionValidator, snapshot/standby ordering, commit/session recovery, active-log retry, timeout/termination fixes | Bounded Rust `snapshot_order` already sorts by term, position, service. Verify relevant local core behavior. Cluster client, service container, durable replicated log, and Archive recovery remain larger runtime work under #18/#19. |
| Tooling/tracing | Java logging becomes tracing; bundled module tests grow; target uses Agrona 2.7.0, SBE 1.41.0, Gradle 9.8.2 | Reference [version catalog](https://github.com/aeron-io/aeron/blob/454da1e4e6c7edf3dd6d34878512d3243384992a/gradle/libs.versions.toml) and wrapper. Verify Java harness prerequisites. Java tracer/CPU fixtures need individual scope decisions; they are not automatically Rust feature requirements or automatically Java-only skips. |

## Ordered implementation slices

Use one focused PR per slice, normally three to five implementation/test files plus required tutorial/documentation updates. If a row grows beyond that, split it by behavior. Each implementation updates matching learner stubs/chapter docs under the owning AGENTS contract. The issue contains progress checkboxes; the IDs below are stable dependencies, not a second status ledger.

### S0 — Pin the reference and make setup reproducible

- Scope: `.gitmodules`, Aeron gitlink, Make setup recipe, and reference instructions. Use SSH for Git operations and exact commit `454da1e4e6c7edf3dd6d34878512d3243384992a`; remove the misleading unused branch-ref behavior. Do not move Tokio/Loom pins incidentally.
- Acceptance: a fresh checkout initializes the exact Aeron revision; rerunning setup cannot advance a branch; the Java harness identifies its source/JAR version and tool prerequisites, with no stale-JAR selection.
- Verify: gitlink/version checks, clean repeat setup, `make check`, Rust process smoke, Java 1.54.0 smoke/soak. A failure stops acceptance and becomes a named prerequisite repair slice; do not carry a red gate onward.
- Dependencies: none. This is the first implementation task.

### S1 — Reconcile the target test inventory

- Scope: `scripts/upstream_tests.py`, its tests, JSONL ledger, baseline/parity docs.
- Acceptance: current inventory reports 335 target paths with added/absent/changed classifications; the resolver move retains historical evidence; all 68 new and 95 changed paths get explicit review dispositions without inheriting full-parity claims.
- Verify: meaningful script tests for added/removed/moved/changed files, `make test-py`, `make test-parity`, documentation build. Keep resolved-count and full-parity reporting distinct.
- Dependencies: S0. Separate reporter correctness from the subsequent method-audit batches if needed.

### S2 — Verify control and frame-layout contracts

- Scope: client protocol/command/CnC/log metadata contracts and Java golden-vector generator.
- Acceptance: supported header/command sizes, offsets, byte order, and version fields are compared at the exact tag; four new flyweight validation families are mapped; matching CnC and control semantic versions stay unchanged unless source evidence requires it.
- Verify: focused `aeron-client` codec/property tests, Java-generated bytes, Java CnC/IPC/UDP smoke. Treat malformed-frame behavior separately from layout equality.
- Dependencies: S0; evidence feeds S3/S4/S6.

### S3 — Reject malformed complete UDP packets

- Scope: receiver, receive endpoint, conductor image insertion, dedicated malformed-packet tests.
- Acceptance: apply target per-type validation to every packed frame before the relevant state/log mutation; cover invalid second frames, impossible lengths/versions/offsets and legal heartbeat/padding cases; valid multi-frame delivery and loss recovery still work.
- Verify: raw-socket driver regression tests and codec/packet property tests; `make fuzz-check` plus bounded `make fuzz` when required tooling is available; IPC/UDP system-test suite.
- Dependencies: S2. Split parser validation and driver integration if the seam exceeds a focused slice.

### S4 — Enforce the target Status Message bounds

- Scope: send endpoint, network publication, focused SM/flow-control tests.
- Acceptance: use 1.54.0 sender-relative position bounds and SETUP special handling; malformed/out-of-range messages cannot move publisher/sender limits; stale legal SMs and legitimate receiver progress still behave correctly.
- Verify: boundary tests around half-term-behind/1.5-terms-ahead limits, term-ID wrap, negative/invalid fields, setup elicitation, and a real two-driver flow-control scenario.
- Dependencies: S2; reuse S3 validation helpers once stable.

### S5 — Prove MPSC ordering and wrap/reuse safety

- Scope: Agrona MPSC/atomic-buffer implementation and Loom models.
- Acceptance: document the Rust reservation/publication protocol relative to upstream claim/unblock behavior; model multiple producers, consumer, full/wrap/reuse and paused producers; only introduce a marker/fence/algorithm change when a failing model or source proof demands it.
- Verify: `RUSTFLAGS="--cfg loom" cargo test -p agrona --lib` under the owning environment, focused normal tests, `make miri` for affected unsafe code, criterion measurements if the hot path changes. Record Loom bounds and limitations.
- Dependencies: S0; independent of Archive feature work after the reference is stable.

### S6a — Modern Archive connection codecs

- Scope: Archive codecs, adapter, Java golden vectors.
- Acceptance: implement template 58 with credentials/client-info variable fields and bounded decode; retire template 2 from the advertised 1.54 boundary or clearly isolate historical support; update schema version to 14 while retaining the correct 1.12.0 runtime semantic version.
- Verify: exact Java byte vectors, truncation/oversize/enum/property tests and codec unit tests. Existing non-connect vectors remain stable where the source diff is unchanged.
- Dependencies: S2.

### S6b — Connect a real Java 1.54 Archive client

- Scope: managed Archive session creation, connection policy, Java interop probe/control-service tests.
- Acceptance: official Java client connects using template 58, records, stops, restarts, lists and replays through Rust; empty credentials work under an explicit permissive policy and unsupported authentication modes fail explicitly; response/session correlation and timeouts are bounded.
- Verify: real Java Archive integration journey and Rust control-service/restart tests. Existing client/driver interop is insufficient evidence for this slice.
- Dependencies: S6a. Full challenge-response authentication is a separate slice if required by the selected policy.

### S7 — Bind Archive control requests to their source image

- Scope: control polling/header identity, session ownership record, real two-client tests.
- Acceptance: carry the establishing image identity through dispatch; another image cannot mutate or close that session, including by reusing request IDs; session expiry/reconnect does not reuse stale ownership.
- Verify: genuine two-publication/client attempts against a running service and positive same-owner requests. Check source ownership before request deduplication and state changes.
- Dependencies: S6b; this is required for accepting the modern managed Archive boundary.

### S8 — Stop affected replays before truncating

- Scope: Archive service/runtime replay cancellation and persistence tests.
- Acceptance: truncation stops all replays of the selected recording before segment deletion, leaves unrelated recordings/replays running, and survives restart with the expected shorter descriptor/data range.
- Verify: control-service test with two active replays plus an unrelated recording; runtime segment-boundary tests and restart/list/replay. Keep purge semantics separately validated rather than assuming truncation rules apply.
- Dependencies: S6b.

### S9 — Close Archive admission and error-path differences

- Scope: split into S9a empty-replay/admission checks and S9b session timeout/abort/cleanup, each with focused tests.
- Acceptance: empty rejected replay does not continue creating resources; start/extend admission uses successful requests rather than lazily created recording sessions; timed-out/failed sessions release their own resources and return accurate errors.
- Verify: managed-service rejection/backpressure/timeout tests and bounded resource counts. Verify existing catalog sync and archiveId/wildcard lookups with multi-Archive tests before changing them.
- Dependencies: S6b/S7; S8 must be green before reusing replay-cleanup behavior.

### S10 — Verify driver lifecycle fixes through live traffic

- Scope: split into S10a live min/tagged receiver timeout, S10b MDC remove/re-add and endpoint closure/resolution, and S10c untethered LINGER/draining cleanup.
- Acceptance: the slowest live receiver still gates correctly, removed destinations stop receiving and can rejoin, and lingering untethered subscribers cannot retain a draining resource forever; avoid tests that only poke impossible raw-tail states.
- Verify: real driver duty-cycle tests with deterministic clock control where possible, resource-count assertions, and IPC/network-spy/UDP scope stated per slice.
- Dependencies: S3/S4; retain existing #10–#14 ownership links for the affected subsystem work.
